# DD1 Android Launcher

[English](README.md) · **한국어**

본인이 소유한 Windows판 Darkest Dungeon을 Winlator 런타임(기기 위의 Wine + Box64)으로
설치하고 실행하는 안드로이드 런처입니다. Steam에 로그인하면 계정이 보유한 빌드를
내려받고, 버튼 하나로 게임이 시작됩니다.

> **비공식 프로젝트입니다.** Red Hook Studios나 Valve가 만들지 않았고, 승인하지도
> 않았으며, 아무 관련이 없습니다. Darkest Dungeon의 이식판이 아니며 게임의 그 무엇도
> 담고 있지 않습니다 — 게임 파일, DLC, 아트, 음원, 세이브, Steam 계정 데이터 어느 것도
> APK와 이 저장소에 없습니다. 이미 보유한 것 외에는 아무것도 내려받지 않고, 게임
> 바이너리를 고치지 않으며, 무료입니다.

## 기능

| | |
|---|---|
| **설치** | QR 또는 비밀번호로 Steam 로그인, 전체 패키지에 걸친 소유 확인, DLC 개별 선택, `files/game`으로의 원자적 설치 |
| **실행** | 버튼 하나. 탭·드래그·홀드를 게임 마우스로 전달하고, 영지 이름은 안드로이드 IME로 입력 |
| **세이브** | 프로필 슬롯별 Steam 클라우드 목록, 내려받기와 올리기, 덮어쓰기 전 자동 스냅샷 |
| **모드** | Workshop 검색·탐색, 구독, 순차 다운로드, 업데이트 감지, 활성/비활성, 로컬 ZIP 가져오기 |
| **배터리** | 해상도, 프로세서 코어, 화면 주사율. 추측이 아니라 서로 비교해 실측한 값으로 고른 것 |

### 배터리

게임에 프레임 제한이 없고 이 구성 어디에서도 걸 수 없어서, 폰이 허락하는 만큼 그리고
그만큼 배터리를 씁니다. Galaxy S25에서 충전을 끊고 잰 값입니다.

| 설정 | 배터리 | CPU 최고 |
|---|---|---|
| 1920x1080, 전체 코어, 120Hz | 24%/h | 83°C |
| 1280x720, 전체 코어, 120Hz | 21.8%/h | 59°C |
| 1280x720, 전체 코어, 번역 빠르게 | 28.8%/h | 63°C |
| **1280x720, 효율 코어, 60Hz** | **14.6%/h** | **56°C** |

두 시간 반이 네 시간 반이 됩니다. 소모의 주범은 픽셀을 그리는 쪽이 아니라 x86을
번역하는 쪽이라, 해상도를 낮춰도 거의 안 움직이는 반면 빠른 코어를 안 쓰게 하면 크게
줄어듭니다. box64의 빠른 프리셋이 오히려 배터리를 *더* 먹는 것도 같은 이유입니다 —
여유가 생기는 족족 아무도 못 보는 프레임을 그리는 데 씁니다.

## 시작하기

빈 폰에서 던전에 파티를 넣기까지입니다. 여기 나오는 건 전부 한 화면에서 끝나고, 나머지는
왼쪽 위 서랍에 있습니다.

### 1. APK 설치

[릴리스](../../releases)에서 내려받아 엽니다. 안드로이드가 두 번 묻습니다. 스토어 밖
앱을 허용할지, 그리고 호환성 경고입니다.

> **"이 앱은 이전 버전의 Android용으로 만들어졌습니다"**
> 정상이며 실수가 아닙니다. Android 10부터는 앱 자기 데이터 폴더에 있는 프로그램의 실행을
> 금지하는데, Wine과 Box64를 푸는 곳이 정확히 거기입니다. 낮은 타깃을 유지하는 것이
> 런타임을 실행할 수 있게 하는 유일한 방법입니다. 그대로 진행하십시오.

### 2. Steam 로그인

런처가 로그인 화면으로 열립니다. 두 가지 방법이 있습니다.

- **QR** — *다른 기기로 QR 로그인*을 누르고 Steam 모바일 앱으로 코드를 찍습니다. 폰에
  아무것도 입력하지 않습니다.
- **계정과 비밀번호** — 입력한 뒤 Steam 가드에서 승인합니다.

> **무엇이 저장되는가**
> Steam이 돌려주는 갱신 토큰뿐이고, 안드로이드 키스토어로 암호화됩니다. 비밀번호는
> 저장되지 않고 로그에도 남지 않습니다.

오른쪽 로그가 확인한 것을 보고합니다. `Reading N Steam licenses` 다음에
`Darkest Dungeon ownership verified`가 나옵니다. DLC는 계정의 모든 패키지에 걸쳐 세니
오래전에 산 번들도 잡힙니다.

### 3. DLC를 고르고 받기

오른쪽에 보유한 DLC가 전부 체크된 채로 뜹니다. **받기 전에 원하지 않는 것을 해제하십시오**
— 해제한 DLC는 애초에 받지 않으므로, 나중에 마음이 바뀌면 따로 받아야 합니다.

> **도살자의 서커스**는 멀티플레이 전용이고 여기서 동작하지 않는 Steam 네트워킹이
> 필요합니다. 빼면 약 540MB를 아낍니다.

**게임과 보유 DLC 다운로드**를 누릅니다. 진행 중에 볼 것:

| 화면 | 의미 |
|---|---|
| `3/8 번째` | 전체 몇 개 중 몇 번째 depot인지. 크기가 심하게 불균등해서 — 본편 하나가 4GB의 대부분입니다 — 한 숫자에 20분씩 머무를 수 있습니다 |
| 퍼센트 | 전체가 아니라 depot별입니다. 한 파트가 끝나면 다시 내려갑니다. 정상입니다 |
| 로그 | 지금 쓰고 있는 파일 이름. 이게 가장 정직한 진행 표시입니다. 이름이 계속 흐르면 데이터가 오고 있는 겁니다 |
| 알림 | 같은 정보가 알림 표시줄에 있어서 화면을 꺼도 됩니다 |

> **Wi-Fi를 쓰십시오.** 이동통신망에서는 Steam이 배정한 콘텐츠 서버가 작은 요청에는
> 답하고 큰 요청에는 응답하지 않아서, 끊긴 것과 구분되지 않는 채로 멈춥니다. 런처가
> 고칠 수 있는 문제가 아닙니다 — 서버는 Steam이 정합니다.

취소하면 받은 바이트만 잃고 DLC 목록으로 돌아옵니다. 실패한 다운로드는 설치본을 건드리지
않습니다. 임시 폴더를 버릴 뿐, 반쪽짜리로 합치지 않습니다.

### 4. 플레이

첫 실행은 런타임을 푸느라 *런타임 준비 중* 화면에서 몇 분 걸립니다. 이후로는 바로
게임으로 들어갑니다.

게임은 첫 실행에서 자기 세이브를 새로 만듭니다. 새 영지가 뜨는 게 정상입니다. 기존
세이브가 있다면 플레이 전에 먼저 내려받으십시오.

### 5. Steam 클라우드에서 세이브 가져오기

서랍 → **세이브**. 프로필 슬롯마다 폰에 있는 것과 클라우드에 있는 것을 나란히 보여주므로,
전송은 항상 방향이 분명한 의도적 행위가 됩니다.

| | |
|---|---|
| 클라우드 슬롯의 ↓ | 폰으로 내려받기 |
| 기기 슬롯의 ↑ | 폰의 사본을 올리기 |
| **스냅샷** | 덮어쓰기 전에 자동으로 남긴 사본 |

온전히 내려받을 수 없는 슬롯은 그렇다고 말하고 아무것도 바꾸지 않습니다 — 반쪽 세이브는
아무도 못 불러옵니다. Steam이 내용 없는 파일을 목록에만 올려두는 경우가 있는데, 보통 실제로
플레이한 적 없는 슬롯이고 *읽을 수 없습니다*로 표시되며 다른 슬롯에는 영향이 없습니다.

> 한 번에 한 기기에서만 플레이하십시오. Steam 클라우드는 두 영지를 합칠 방법이 없습니다.

### 6. 모드

서랍 → **모드 관리자**. PC를 포함해 어디서 구독했든 화면을 열 때 내려받고, 거기서 구독을
해제한 것은 여기서도 지워집니다.

| 탭 | 내용 |
|---|---|
| **Workshop** | 이름으로 검색하거나 Workshop 주소·ID를 붙여넣습니다. 인기·최신·평점순 정렬, 격자 버튼으로 2·3·4열 전환. 카드를 누르면 전체 설명과 스크린샷이 나옵니다 |
| **내 모드** | 설치된 것, 업데이트가 있는 것, 꺼둔 것. **ZIP 가져오기**로 직접 넣을 수도 있습니다 |

다운로드는 한 번에 하나씩 돌고 알림이 어느 것인지 알려줍니다: `3/12 · Plague Doctor
skins mod · 42%`. 모드가 온전히 도착하기 전에는 게임 폴더에 넣지 않고, 게임이 실행 중일
때는 건드리지 않습니다.

그 다음 **게임 안에서** 캠페인 화면에서 모드를 켭니다. 그 목록은 세이브의 일부이고 런처는
세이브를 편집하지 않습니다.

### 7. 오래 쓰기

서랍 → **설정**. 기본값도 안전하지만 바꿀 만한 것들입니다.

| 설정 | 이유 |
|---|---|
| **해상도 → 1280x720** | 게임은 어차피 720p로 그립니다. 픽셀은 줄고 CPU 최고 온도는 24°C 내려가며 눈에 보이는 차이는 없습니다 |
| **프로세서 코어 → 효율 코어만** | 단일 항목으로 가장 큰 이득입니다. [배터리](#배터리) 참고 |
| **화면 주사율 → 게임 중 60Hz** | 패널은 게임과 무관하게 120Hz로 돕니다 |
| **명령어 번역 빠르게** | **끄십시오.** 빨라진 만큼 아무도 못 보는 프레임을 그리는 데 쓰고, 시간당 7%를 더 먹습니다 |

## 터치 조작

| | |
|---|---|
| **탭** | 좌클릭 |
| **드래그** | 좌클릭 유지 — 파티 이동, 가방 안 아이템 옮기기 |
| **꾹 누르기** | 우클릭 — 영웅에게 아이템 사용 |
| **네 손가락** | 런처 서랍 |
| **ESC** / **ABC** | Esc 키, 영지 이름 입력용 안드로이드 키보드 |

탭하면 커서가 그 자리에 남습니다. 툴팁은 그렇게 뜹니다 — 아이템을 건드리면 설명이
나옵니다.

## 요구사항

- ARM64 안드로이드 기기, Android 8 이상
- Darkest Dungeon(앱 `262060`)을 보유한 Steam 계정
- 여유 공간 약 5GB — 게임이 4GB 남짓이고 staging에도 자리가 필요합니다
- **Wi-Fi.** 이동통신망에서는 Steam이 배정한 콘텐츠 서버가 작은 요청에는 답하고 큰
  요청에는 응답하지 않는 일이 잦아 다운로드가 멈춥니다

## 빌드

Android SDK 34, NDK `24.0.8215888`, CMake 3.22.1이 필요합니다.

```sh
./gradlew assembleDebug testDebugUnitTest    # 모든 변경이 통과해야 하는 것
./gradlew assembleRelease                    # keystore.properties가 있으면 서명됨
```

릴리스 서명은 저장소 루트의 `keystore.properties`를 읽습니다. 파일이 없으면 실패하는
대신 미서명 APK를 만듭니다.

```properties
storeFile=dd1-release.jks
storePassword=...
keyAlias=dd1
keyPassword=...
```

## 테스트

단위 테스트는 호스트에서 돌고, UI 테스트는 Gamescope 창의 Waydroid에서 돕니다.
Waydroid의 x86_64 브리지로는 ARM64 런타임을 실행할 수 없어서, 게임 구동 자체는 항상
실기기에서만 검증됩니다.

```sh
./gradlew connectedDebugAndroidTest          # Waydroid 전용
```

게임이 설치된 폰에는 계측 테스트를 절대 돌리지 마십시오. Gradle이 끝나고 앱을 지우면서
4GB 설치본과 Wine 프리픽스를 함께 가져갑니다.

## 알아둘 것

`applicationId`는 `com.winlator`로 고정입니다. Winlator 루트 파일시스템이
`/data/data/com.winlator` 경로를 box64의 ELF 인터프리터, wineserver, ntdll,
`ld.so.cache`에 고정 길이 필드로 구워 두었기 때문에, 바꾸려면 같은 길이의 id와 추출된
트리 전체를 다시 쓰는 작업이 필요합니다.

`targetSdkVersion`은 28로 둡니다. Android 29부터는 앱 데이터 디렉터리의 파일 실행을
금지하는데, 런타임이 box64와 Wine을 푸는 곳이 정확히 거기입니다. 안드로이드가 띄우는
호환성 경고는 그래서 나오는 것이며 정상입니다.

## 이것이 아닌 것

Darkest Dungeon은 Red Hook Studios의 것이고, EULA는 개인 플레이 목적의 사용을
허락합니다. 이 런처가 하는 일이 정확히 그것입니다 — 직접 구매한 Windows 빌드를 고치지
않고, 본인 소유의 기기에서 실행합니다. 이식판이 아니며 게임을 재배포하지도 않습니다.
게임을 보유한 본인의 Steam 계정이 없으면 이 런처는 실행할 것이 없습니다.

공식 iPad판이 있습니다. 태블릿에서 Darkest Dungeon을 하고 싶고 기기가 맞는다면 그쪽을
구매하십시오. Red Hook이 수익을 얻는 버전입니다.
